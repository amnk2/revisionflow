Most hash functions are imperfect, so two different keys can end up with the same index. This is called a collision, and every hash table needs a way to handle it. The first common strategy is separate chaining, where each slot holds a linked list of all the entries that hashed to it. The second is open addressing, where, if a slot is already taken, we probe through the table looking for the next free slot. How well either strategy works depends on the load factor, which is the number of entries divided by the number of buckets. When the load factor gets too high, the table is resized and every entry is rehashed.
